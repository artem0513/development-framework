# Skill compatibility and project routing

User instructions and applicable repository policy define scope and authorization. Installed skills supply methods; their examples and historical run records grant no access, assignment or publication permission.

Choose one leading workflow for the request: project-bootstrap for setup, task-intake for assignments/meetings, task-discovery for relevant context/capabilities, project-context-manager for continuity, task-orchestrator for managed execution, the independent roles for judgments, communication/time roles for drafts. Select software, infrastructure, document, research or mixed profiles by the actual requested action. Finance analysis and document warnings do not become software work. Optional methods can assist the selected workflow without creating another coordinator or approval interview. Load only the conditional reference needed for the active step. Resolve conflicting methods against current project instructions and user intent; disclose a material conflict.

Keep requirements in the confirmed task contract, execution handoff in the latest SQLite checkpoint, original evidence in referenced artifacts, and receipts in the existing gate. A different chat is not a different task. A copied profile is not authority. Per-project repository/source paths, identities, providers, branch conventions and publication rules are supplied during adoption; never inherit them from a donor project.

Restore before replacing tasks/branches/PRs. Parent/child tasks need explicit acceptance mapping; a ready label is not assignment. Distinguish implemented, checked, independently verified, committed, published and merged. Before an authorized PR/publication, inspect current target/head and conflict status; unknown mergeability remains unknown. Checkpoint before a handoff. No automatic pushes, closes, merges, sends or schedules arise from this routing reference.

For a user-selected failing GitHub Actions PR, optionally use gh-fix-ci to collect scoped checks/logs and summarize the failure. Its result does not replace local tests, independent judgments or the gate. Do not run remote CI diagnosis during ordinary bootstrap or infer access from an installed skill.

When independent ready parts benefit from available permitted native subagents, follow task-orchestrator's parallel-work reference. One lead owns the graph, integration, approved scope and shared budget; keep explicit read/write ownership, dependency barriers and persisted budgets. Recompute ready waves after each result, queue excess capacity, preserve root leases/CAS and keep shared-root mutation serialized. Missing optional native delegation uses the serial workflow without a new interview; native advisory answers do not replace formal Runner receipts.
