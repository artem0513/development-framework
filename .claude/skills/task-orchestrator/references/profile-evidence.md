# Profile evidence

Select a profile by the requested action. A finance report's data warnings are not software debugging; changing the generating code is software. Mixed tasks map every obligation to stages and child tasks without weakening parent coverage.

Apply the [readiness proof boundary](evidence-decisions.md#3-check-the-readiness-the-obligation-actually-needs) when allocating profile evidence. Current acceptance uses proof causally attainable before its gate; later authorized effects remain mandatory in the publication/finish plan or delivery task and pending until checked. A whole-task publication gate includes all its stages, so stage reassignment alone cannot separate future proof. Phase-local source approval does not establish publication, postconditions or overall completion.

| Profile | Evidence to collect |
| --- | --- |
| software | Executed mandatory commands, positive test counts, no skipped required tests, independent AC and code review, current source/contract/plan fingerprints |
| infrastructure | Actual resource identity, before/after observations, operation intent and reconciliation, independent postcondition evidence; no invented resource success |
| document | Required artifact, readable rendering/structure where applicable, required content and traceable sources, independent acceptance and substantive review |
| research | Sources and dates, claim-to-source coverage, clear inference and uncertainty, independent acceptance and substantive review |
| mixed | Required parent coverage across all child profiles and stages; no completed parent while mandatory children remain unresolved |

Configured evaluators determine executed facts; model judgments remain separate. `manual` evidence has no recording command and cannot pass; use an artifact, test, command or probe evidence kind with its source instead. A protocol test establishes the protocol only. Missing mandatory resources or independent execution remain BLOCKED. Local reliability records do not enforce publishing against another process with the same OS identity; trusted CI and server rules are required for that boundary.
