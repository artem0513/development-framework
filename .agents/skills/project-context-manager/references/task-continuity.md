# Task continuity

Use on start, resume, task switching, significant changes, test results, decisions, blocker changes and before a final handoff. Resolve the registered project/workspace and existing task ID with `ase context`; source identity (for example a full issue URL) is a locator, never authorization. Reuse the same task across chats and backends on this computer. Do not create chats automatically.

Run `restore TASK` before continuing. It returns the contract, checkpoint, source coverage, current Git observations and drift. Reconcile branch, full SHA, dirty/untracked work and errors against saved observations; preserve newer or staged work. Git errors are unknown, not a clean checkout. Reading state does not fetch, checkout, reset, publish or run project scripts.

Use `continuity-snapshot TASK` to obtain the expected checkpoint revision. Prepare a concise JSON payload using templates/checkpoint.json, then `checkpoint TASK --expected-revision N --file PATH`. Record stage, summary, one precise next_action, blockers and source_refs. The runtime captures Git observations. A stale revision fails; reload, merge facts and retry. Never bypass rejection with an old summary. Historical checkpoints remain in SQLite. Markdown exports are disposable views. Decisions and session summaries remain available for concise retrieval; they cannot overwrite the canonical checkpoint.

Store evidence references, not raw chats, secrets or full transcripts. Preserve original-assignment authorization, affected-stage gap mapping and original-problem progress/diagnostic/probe history across aliases, delegates and resumes. Rewording a failure or splitting a stage cannot reset history or explicit limits. After an owner answer refresh affected assumptions and dependent evidence; retain unchanged independent approval. Missing requirements, approvals or evidence remain unknown. A checkpoint is active-agent persistence, not guaranteed background autosave or a shutdown hook. An interruption preserves only the last completed transaction. Resume never means re-execute external side effects; UNKNOWN must reconcile first, and nonvisibility alone is insufficient.

On requested stop, end of session or waiting for approval/blocker resolution, use task-orchestrator's finish-and-reports reference to save a dated atomic `ase session finish` closure with reason, evidence, blockers and one exact next action. Session closure does not by itself complete the task. Worklog and meeting reports query local recorded activity; they do not send it externally or infer billable time.
