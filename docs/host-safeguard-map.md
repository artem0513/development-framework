# Retirement map for the verification coordinator

This is the closed test-by-test mapping required before removing `ase/host.py` and its MCP transport tests. Protocol fixtures below prove subprocess/configuration behavior, not live model acceptance. Historical host tests are not silently treated as successful coverage of the new controller.

The Git adapter retains helper/hook/ambient-config/protocol suppression; publishing keeps its separate ordinary-Git authorization path.

## Changed trust boundary

The former host's configured roots also constrained Git metadata/commondir before entering the unsandboxed coordinator. That privileged service is removed. The local explicit selected project and read-only inspector remain, with target code/config excluded from backend startup and packet-only backend input. The old coordinator-wide allowlist and job lifecycle are not represented as active controls in the portable CLI. Linked worktree metadata needs an explicit metadata-scope policy if a future privileged service is added; do not claim this map establishes such a service boundary or silently reject valid worktrees as a substitute. Same-user hostile modification remains outside enforcement.

## Execution status

Direct inspection and boundary tests are run and logged during retirement, together with Runner/adapter/profile/gate/project suites. The newly exposed Windows acquisition error in the root-task lock was normalized by the controller owner and its actual cross-process test now passes. All 18 former cases are mapped above (17 HostTests and one stdin test). Source host.py and transport-only test_host.py are removed; `ProcessInputBoundaryTests.test_retired_coordinator_module_is_not_an_active_cli_service` proves the former CLI module is unavailable. No test deletion is justified by source-string matching. Final check commands and exact file hashes are recorded in outputs/universal-workflow/host-retirement-report.md.
