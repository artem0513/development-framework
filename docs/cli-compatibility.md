## Codex probe

Запуск использовал `exec --ignore-user-config --ephemeral --sandbox read-only --skip-git-repo-check` с отдельной output schema и отдельным процессом на каждую роль. Auth не копировался, execpolicy rules не отключались и sandbox не расширялся.

Первый probe запросил чтение файла дочерним shell tool. Tool call был отклонён policy. Модель сообщила об отсутствии доступа; нулевой exit процесса не был принят за успешную проверку.

Второй probe передал родительским runner фактическое содержимое одного исходного файла, SHA-256 и два требования. Обе свежие сессии выявили возврат `0` вместо `ZeroDivisionError`. Это подтверждает packet-only транспорт и независимое обнаружение конкретного дефекта, но не доступ дочернего shell к репозиторию.

Пакет всегда должен сообщать границы охвата. Неполный пакет не превращается в полный анализ; missing coverage блокирует соответствующий обязательный критерий. На Windows большой пакет передаётся контролируемым stdin pipe, не чрезмерно длинным argv и не наследованием stdin родительского чата.

У проверенной версии Codex выявлен дополнительный предел: один prompt не больше 1 048 576 символов. Попытка передать почти 2 млн символов была отклонена до модельной работы; её receipts не считались приёмкой. Для итогового ревью сохранены полные runtime/skills/scripts, критические тесты и точная опись остального покрытия. Размер пакета необходимо проверять по реальным ограничениям CLI, а большой проект исследовать по обоснованным областям.

Локальные raw evidence находятся в `outputs/universal-workflow/packet-{ac,review}.*`. Они не являются переносимым доказательством без проверки исходных файлов и хэшей. Baseline suite до runtime-изменений: 179 тестов, OK, 121.110 секунды.

## Первичная оценка риска других backend

Общие Python/SQLite/state/gate-механизмы не зависят от модели. Основной риск переноса находится на границе CLI: загрузка пользовательских hooks/extensions, permissions, auth, terminal events, завершение процесса и structured output. Отдельный успешный parser fixture подтверждает только обработку известного формата.

До живой проверки риск Claude оценивается как средний для формата результата и высокий для полного end-to-end запуска с конкретной auth/permission-конфигурацией. Для Copilot риск высокий на уровне неизвестных вариантов terminal events и clean-start controls. Это качественная инженерная оценка, а не измеренная вероятность отказа.

При отсутствии подтверждённых controls адаптер должен выдавать явное ограничение вместо ослабления permissions или имитации live success. Выбор провайдера остаётся явным.
