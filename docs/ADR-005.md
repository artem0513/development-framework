# ADR005 — Project-owned runtime and private state

Date: 2026-11-12. Status: accepted for the user's requested project-local mode; legacy shared mode remains supported.

Use explicit `--project-local` installation to keep runtime, settings and native agent files in a selected project. Runtime/configuration live in `.devframework`; persistent memory, journal, receipts, logs, vault and backups live in `.devframework/local`. The selected project's three backends share that state, and other projects have separate registries/identities. Explicit `--home` remains an intentional override. This extends the previous outside-workspace state restriction only for a validated exact reserved local home, not arbitrary application paths.

The private directory is protected by a final `/local/` rule in `.devframework/.gitignore`, effective Git exclusion where Git is present, and rejection of any tracked private path. Redirected/shared-inode managed files are rejected. Generic discovery, knowledge, source packets and fingerprints exclude private paths and reject hardlinked source aliases before reading. The installer preflights targets/backups and repairs ignore protection before creating private backups. Native provider account/session caches are not relocated; no user credentials were supplied for this implementation.

Local configuration is selected before shared environment/default state and follows the explicit selected root instead of unrelated cwd. Relative launchers select their owning project and require its config; explicit project/repo/home selectors retain their purpose. Missing/incompatible local identity after relocation requires explicit attachment/recovery, preserving UUID and requiring new workspace-bound observations. Existing shared state is not silently migrated.

Independent CLI execution keeps a clean owned external temporary cwd while persistent evidence stays private inside the project. Native skill roles are project-scoped; there is no framework MCP, daemon, provider-home forcing or permission relaxation. Trust remains the same as ADR001: local files/prompts/hashes protect against mistakes, not another hostile process with the same OS identity; trusted CI/server rules are required for enforced remote publishing.
