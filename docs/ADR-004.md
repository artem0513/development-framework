# ADR 004 — Portable local CLI workflow without framework MCP

Date: 2026-11-12. Status: accepted for the universal workflow implementation. Supersedes the active transport/registration design in [ADR 002](ADR-002.md); its historical evidence remains intact.

## Decision

Use canonical portable skills, Python 3.11+ standard-library services/CLI and isolated local SQLite state. Codex, Claude Code and Copilot adapters share that runtime and explicit project/workspace identity. No framework MCP server, persistent service or mandatory agent SDK is required. Independent execution capability and permission are probed, never inferred from an installed descriptor.

A single canonical `skills/` set contains eleven packages. `build_assets.py` generates backend-native role pointers; project installers copy the same skill bytes to `.agents/skills`, `.claude/skills` or `.github/skills` and preserve local rules. Universal managed tasks choose software, infrastructure, document, research or mixed profiles by the actual action. Domain analysis does not silently become software engineering. Optional workflow libraries are methods, not another source of authority.

Installation is explicit and previewable. `plan_install` returns exact owned files, hashes, prior hashes and backups without mutation. `apply_install` rejects stale inputs and preflights all destinations/backups, including link/hardlink/type conflicts. Runtime-only setup does not activate routing. Explicit legacy Codex global mode remains opt-in; defaults do not activate projects globally. Launchers do not change provider auth/homes or permissions. These are local accident barriers rather than same-user tamper protection or full filesystem transactions.

The historical `--register-verifier` flag now produces an explicit no-write deprecation error. Existing user registrations are preserved. `plan_mcp_cleanup` previews only a recognizably owned historical ASE entry; `apply_mcp_cleanup` requires an observed explicit migration authorization reference, checks stale config and backs up before removing exactly that server subtree. Unrelated integrations, auth, hooks, permissions and user text remain unchanged. Unsupported/ambiguous shapes fail closed. User installation migration requires separate authority.

## Preserved safeguards

Mandatory profile evidence, original requirements, exact proposal/stage approval, source/contract/plan fingerprints, runner-captured check facts, independent acceptance/review, P0/P1/P2 blocking, persisted budgets, protected paths, high-risk authorization, external-effect reconciliation and publication dry-run remain runtime responsibilities. A missing optional transport cannot block usable local operations; missing mandatory independent capability does block approval. Agent text and protocol fixtures cannot create real receipts or live support.

State selection is explicit `--home`, then `ASE_HOME`, then the platform AutonomousSE directory. Memory is local to this computer with project isolation, revision checks, source freshness/history and dated session closure. Export/import is explicit; cloud agents and other computers do not automatically obtain it. Raw recordings/chats and provider credentials do not belong in SQLite.

## Verification and limits

Disposable filesystem/configuration tests cover all three packaging targets and the local protocol. They do not install into the user's active Claude/Copilot environment or claim live subscriptions/verification. Codex consuming-agent and live runtime evidence are recorded separately. String assertions and file hashes establish packaging only, not model routing. The old ADR's Codex startup problem is an environment capability limit to report, not permission to copy credentials or weaken sandbox policy.

Local receipts, prompts and hooks cannot enforce publishing against a hostile process with the same OS identity. Use a pinned trusted CI runner, separate credentials and server-side required checks for enforcement, as in [ADR 001](ADR-001.md).
