# ADR 003 — Project opt-in instead of global engineering routing

Date: 2026-11-03. Status: accepted design; execution evidence is recorded by the project-opt-in task.

The user uses Codex for financial reports, documents and software work. A globally required engineering coordinator and globally discoverable engineering packs can route domain analysis into debugging or development procedures. DevelopmentFramework must instead remain a reusable template until a named software project explicitly adopts it.

The installer now requires explicit project, runtime-only, verifier-only or legacy global intent. Project adoption places owned skills, native roles and routing in the selected repository and enables only its exact skill copies. Runtime preparation and verifier registration remain separate from adoption. Vendor installation requires an explicit destination. Existing configuration and the sandbox/host verification boundary are preserved.

The local migration backs up and removes only managed global engineering routing, disables recorded global engineering skill paths, and moves owned native roles to project scope. Exact paths avoid suppressing project copies with the same name: live host discovery showed that a global name disable could prevail over a project path enable. It preserves finance/domain skills, application tools, unrelated user configuration and existing verifier roots. Global source copies may remain as an inactive library. Already-injected chat context requires a host refresh.

This supersedes ADR 001's global installation default, not its evidence gate or same-user trust boundary. Skills and local file hashes are not security enforcement. Semantic adoption checks, executed tests and independent AC/review remain distinct evidence; a project copy alone does not grant MCP access or publishing authority.
