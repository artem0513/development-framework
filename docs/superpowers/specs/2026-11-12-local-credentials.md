# Local credentials and on-demand access

User authorized implementation after choosing one local import file, encrypted storage, lazy login/session reuse, no framework MCP, shared by Codex/Claude/Copilot and questions only for genuine blockers. This extends the previous no-auth-copy default for explicitly imported service profiles; it does not authorize reading or migrating existing provider credentials.

## Decisions

Use Python stdlib JSON and Windows DPAPI CurrentUser (`CRYPTPROTECT_UI_FORBIDDEN`) for an encrypted vault at `ASE_HOME/credentials/vault.json`, outside project state and source. No plaintext fallback on unsupported OS. The Windows account/machine protects persisted bytes; this is not isolation from malicious code running as the same OS user. Keep the import file unchanged, require it outside Git/source, never include its bytes in SQLite/model packets/export/logs. All tests use disposable fake credentials, never existing user credentials.

Import schema: `{"schema_version":1,"credentials":[{"id":"vm-lab","target":"https://lab.example","kind":"environment","secrets":{"username":"...","password":"..."},"env":{"LAB_USER":"username","LAB_PASSWORD":"password"},"session":{"probe":{"argv":["ABSOLUTE_EXECUTABLE","..."],"timeout":30},"login":{"argv":["ABSOLUTE_EXECUTABLE","..."],"timeout":60}}}]}`. Session is optional. Kinds: `environment`, `http-basic`, `http-bearer` (basic requires username/password; bearer requires token). Target is an exact normalized HTTPS origin with no embedded credentials/query/path; explicit HTTP loopback is permitted solely for local services/tests. No cross-origin redirects. `env` maps child environment names to secret fields, never interpolates secret values into argv.

Vault public API: `CredentialVault(home)`, `import_file(path)` (atomic validated batch; idempotent same entries; same target rotation allowed, target rebind rejected), `list()` (safe metadata only), `resolve(ref,target)` (internal execution-only profile including per-entry integer `revision`), `configure(ref, target, config)` (only nonsecret env/session changes; target immutable), `update_secrets(ref,target,changes,expected_revision)` (CAS per-entry; merges other entries under OS lock). Encrypted payload schema version plus per-entry revisions; bounded JSON, no duplicate keys/IDs, safe generic errors, atomic temp+replace, redirected/shared state rejected, process-safe locks. `metadata(ref,target)` never returns secret values. Removal is explicit. No CLI secret-export/show command.

Common access API: `CredentialAccess(vault)`. `ensure(ref,target,timeout=60,cancel_requested=None)` probes an existing CLI session, logs in at most once only on explicit `login_required`, then probes again. Probe/login JSON protocol has `status` in `authenticated`, `login_required`, `interaction_required`, `unavailable`; login may return `secrets` with replacements for existing secret keys, persisted encrypted by CAS before reuse. Probe/login raw stdout/stderr never persisted or returned; only whitelisted status/receipt metadata. No recipe means environment preparation, not a false live-authentication claim. Real interaction/invalid credentials/unsupported CLI are typed blockers. Commands use an external trusted cwd, shell=False, owned cancellation/timeout/output limits; no automatic platform-permission changes.

`run(ref,target,argv,cwd,log,timeout=300,cancel_requested=None)` ensures access lazily, injects only this profile's secrets into the child environment, executes through core.execute with literal/encoded-value redaction, and returns safe `access` metadata including credential revision. Never mutate parent/model environment. `request(ref,target,path='/',method='GET',timeout=30)` supplies HTTP basic/bearer auth for GET/HEAD observations with TLS verification, exact-origin checks, no redirects and safe bounded response; HTTP mutation/provider-specific GUI login is not a universal built-in claim. Services requiring another protocol use a configured CLI adapter/recipe; absent support is a genuine blocker.

Runtime integration: checks and infrastructure actions can declare `access:{credential_ref,target}` containing references only. Require current task/stage approval and the exact origin in that stage's approved resources. Keep normal check/action plan/source bindings and budgets. Infrastructure observation and mutation both use the same access; UNKNOWN reconciliation remains unchanged. Final gate validates the captured credential revision against safe vault metadata; rotation/configuration invalidates affected evidence. No access grants from credentials alone.

CLI: global `credentials import --file`, `credentials list`, `credentials configure REF --target ORIGIN --file` operate on the common home without creating a project. `access ensure TASK --stage STAGE --credential REF --target ORIGIN` requires current approval, declared access and target scope. Normal `check/run/resume` automatically use declared access. All three bots call the same CLI; no extra per-bot credential copies. Update canonical skills with reference-only handling and typed real-blocker behavior.

## Acceptance

Real Windows DPAPI roundtrip/tamper/no-plaintext bytes; atomic invalid batch/idempotence/rotation/rebind/CAS/concurrent import; metadata/import errors contain no canaries. Real subprocess and local HTTP fixtures verify lazy first login, session reuse/relogin/refresh, target isolation, redirects/TLS policy, environment isolation, bounded cancellation/failures and no canaries in logs/SQLite/model packets/exports. Public CLI check/action scenarios retain approval/source/profile/UNKNOWN gates, credential revision invalidation and backend-neutral routing. Full unittest on Python3.12/3.15, clean package checks and actual independent Codex AC/review follow a coherent freeze. Claude/Copilot receive shared CLI/descriptor checks, not fabricated live tests.
