The owner authorized both P2 fixes from the additional six-rule review, three missing behavioral scenario families, Codex tests, repeat independent review and publication to the existing repository. Routine implementation choices remain delegated.

## Decisions

Generated package data contains the vetted current role skill, six evidence rules and applicable profile guidance. Canonical skills remain the authored source; build_assets generates ase/data/runtime_policy.json and detects drift. The runtime reads only its own package resource, never policy discovered in client source, cwd or environment. The wheel and existing recursive installers carry that resource for all three backends.

WorkflowController supplies a reserved handoff.runtime_policy. Raw Runner callers may omit it and receive the host bundle; any supplied policy must exactly match the current role. The prompt explicitly activates this host field and keeps project source/logs as data. Policy tool/retrieval instructions do not expand the closed session's permissions. Adapter sandbox, tool restrictions, byte limits and no-MCP operation remain unchanged.

Policy identity covers canonical bundle contents and loader/formatter code. It enters the source fingerprint, leaving existing receipt binding keys and database schema unchanged. Actual captured request and delivered stdin/argument prompt must agree. Current approval/progress/diagnostic evidence requires current policy. Explicit historical verification preserves older source/proposal/action provenance without granting new approval or replaying known effects; legacy captures stay visibly unbound.

Current acceptance criteria require proof causally attainable before their gate. Their own approval and subsequent publication/SHA/closure cannot be prerequisites for that approval. Later delivery remains a mandatory, pending owner-goal obligation checked before final completion. Publisher's whole-task gate means moving future proof to another stage of the same task is not a sufficient separation.

AC missing_coverage contains only unmet proof for the current criterion/gate; nonblocking limits and pending downstream requirements belong in limitations and the delivery plan. A PASS paired with a future destination in missing_coverage was observed to block correctly at the mechanical gate; the role guidance/output-schema descriptions now remove that ambiguity without relaxing rejection. An owner answer is recorded in the exact task/proposal authorization before resume, not left solely in an external test log.
