# ADR 001 — Native Codex with an evidence gate

Date: 2026-11-01. Status: accepted for local implementation; remote enforcement requires repository-owner CI configuration.

Use installed Codex CLI 0.166.0-alpha.5.1 for implementation and separate read-only `codex exec` sessions for AC verification and code review. Preserve native model selection and existing user configuration. Use Superpowers from the current official marketplace for planning, debugging and development practices; do not recreate its methodology. Evaluate vendor skills on demand by detected stack, not a blanket installation. Spec Kit is an optional alternative specification workflow, not a second mandatory orchestrator. See [research](research.md) for sources and compatibility matrix.

Custom code fills the evidence gap: a small dependency-free Python CLI (the request permits a maintainable local application other than .NET), SQLite project-isolated memory, subprocess receipts, revision fingerprints, stale-evidence rejection, bounded orchestration, reports and dry-run publishing. Python 3.15, Git 2.56 and .NET SDK 10.0.401 were actually detected. SQLite ships with Python, avoiding a package supply chain solely for storage.

Trust boundary: prompts, user-owned files, hashes and Git hooks detect mistakes but cannot constrain a malicious process with the same Windows identity and filesystem rights. Separate verifier sessions provide independent judgment, not an OS security identity. Enforced publishing requires a protected CI check running a pinned trusted gate outside the feature branch, minimal credentials and required branch protection. No such protection is claimed to be configured on client repositories. Automatic remote pushes remain disabled by default.

Implementation sequence: core SQLite/runner/gate; integration tests; global skills and agents plus backed-up installation; controlled disposable Git demonstration; independent review and AC audit; corrections and final evidence report. Parallel work uses disjoint file ownership. An unavailable independent verifier blocks approval rather than falling back to self-review.

Acceptance: actual commands and positive test counts; mandatory AC evidence from an independent session; blocking review findings prevent approval; fingerprints invalidate stale reports; protected-path changes reject; zero tests/missing tool/failed build fail closed; state survives restart and remains project-isolated; dry-run is default and disposable local remote exercises safe publishing; report limitations explicitly.
